# Gasem

**Gasem** — компилируемый язык для написания загрузчиков и системного ПО.
Синтаксис в стиле ассемблера x86, но операнды разделяются **дефисом**, а не запятой:

```
mov ax - 1
```

Компилятор `gasem` превращает исходник `.gsm` прямо в машинный код x86
(16 и 32 бит) — в плоский двоичный файл, который можно записать в загрузочный
сектор и запустить. Ассемблер (NASM и т. п.) не нужен.

## Быстрый старт

Нужен только Python 3.8+ (без сторонних библиотек).

```sh
python3 -m gasem examples/hello.gsm                # → examples/hello.bin (512 байт)
qemu-system-i386 -drive format=raw,file=examples/hello.bin
```

или сразу собрать и запустить в QEMU:

```sh
python3 -m gasem run examples/hello.gsm
```

Установка как команды `gasem`:

```sh
pip install .
gasem boot.gsm -o boot.bin
```

# Документация языка

Та же документация одним текстовым файлом: [`docs/gasem.txt`](docs/gasem.txt).

## Общее

- Исходник — текстовый файл в UTF-8, обычно с расширением `.gsm`.
- Одна команда на строку. Комментарий начинается с `;` и идёт до конца строки.
- Имена команд, регистров и директив не зависят от регистра букв (`MOV` = `mov`),
  имена меток — зависят.
- Регистры: `al cl dl bl ah ch dh bh`, `ax cx dx bx sp bp si di`,
  `eax ecx edx ebx esp ebp esi edi`, сегментные `es cs ss ds fs gs`,
  управляющие `cr0 cr2 cr3 cr4`, отладочные `dr0`–`dr7`.

### Разделитель операндов

Операнды разделяются **дефисом, окружённым пробелами**: ` - `.

```
mov ax - bx          ; два операнда
imul ax - bx - 10    ; три операнда
mov ax - -1          ; второй операнд — число -1
```

Дефис **без пробелов** — это минус: `510-($-$$)`. Внутри скобок `( )` и `[ ]`
дефис всегда означает минус, поэтому можно писать `[bx - 2]` или `(a - b)`.
Запятая — ошибка (компилятор подскажет).

### Числа и строки

| Запись                    | Значение                                   |
|---------------------------|--------------------------------------------|
| `1234`, `1_000`           | десятичное                                 |
| `0x7C00`, `0FFh`          | шестнадцатеричное                          |
| `0b1010`, `0o17`          | двоичное, восьмеричное                     |
| `'A'`, `'AB'`             | символы как число: `'A'` = `0x41` (до 8 байт, младший — первый) |
| `"Hello"`                 | строка: в данных и в `do` — байты строки; в команде — **адрес** строки (см. «Строки в командах») |

В строках работают escape-последовательности: `\n \r \t \0 \\ \" \' \xNN`.
Строки кодируются в UTF-8.

## Метки и константы

```
start:                ; метка — адрес следующей команды
loop: dec cx          ; метка и команда на одной строке
msg b: "Hello" - 0    ; переменная: метка без двоеточия перед данными
.next:                ; локальная метка — принадлежит последней глобальной
SIZE = end - start    ; константа (то же: SIZE equ end - start)
```

- Ссылаться можно и вперёд, и назад — компилятор делает столько проходов, сколько нужно.
- В константах нет операндов, поэтому ` - ` там — обычный минус: `SIZE = end - start`
  (то же самое в условиях `if`/`while`).
- Локальная метка `.next` после глобальной `print` на самом деле называется
  `print.next`; так к ней можно обратиться из другого места.
- В именах можно использовать буквы любого алфавита (в том числе кириллицу), цифры, `_` и `.`.
- Зарезервированы (не могут быть именами): регистры, `b w d q s`, `byte word dword qword`,
  `short near far`, `a20`, `og align include incbin do equ pool args`.

## Директивы

| Директива                         | Значение                                                 |
|-----------------------------------|----------------------------------------------------------|
| `og 0x7C00`                       | адрес загрузки (org). Один раз, до первой команды         |
| `b 16` / `b 32`                   | режим процессора (bits). Можно переключать по ходу программы |
| `align N`                         | выровнять адрес до кратного N (заполнение — `nop`)        |
| `align N - байт`                  | то же, заполнить указанным байтом                         |
| `include "файл.gsm"`              | вставить текст другого файла                              |
| `incbin "файл"`                   | вставить двоичный файл как есть                           |
| `incbin "файл" - смещение - длина`| вставить часть двоичного файла                            |

Пути в `include`/`incbin` считаются от папки текущего исходника.

## Команды

### Команды Gasem

| Gasem          | x86        | Описание                              |
|----------------|------------|---------------------------------------|
| `mov ax - 1`   | `mov`      | переместить                           |
| `xor ax - ax`  | `xor`      | исключающее ИЛИ                       |
| `int 0x10`     | `int`      | прерывание                            |
| `nxtb`         | `lodsb`    | следующий байт: `al = [si]`, `si += 1` |
| `nxtw`, `nxtd` | `lodsw`, `lodsd` | следующее слово / двойное слово |
| `chk al - al`  | `test`     | проверка (логическое И без записи результата) |
| `jfnz метка`   | `jnz`      | переход, если не ноль                 |
| `jmp $`        | `jmp`      | безусловный переход (`$` — сама эта строка, т. е. вечный цикл) |

Условные переходы Gasem: `jf` + условие. Все варианты:
`jfz jfnz jfe jfne jfc jfnc jfa jfae jfb jfbe jfg jfge jfl jfle jfs jfns jfo jfno jfp jfnp`
(а также синонимы `jfna jfnb jfnae jfnbe jfng jfnl jfnge jfnle jfpe jfpo`).
Стандартные имена x86 (`jnz`, `lodsb`, `test`) тоже работают.

### Остальные команды x86

| Группа              | Команды |
|---------------------|---------|
| пересылка           | `mov xchg lea movzx movsx lds les lss lfs lgs push pop pusha popa pushad popad pushf popf pushfd popfd` |
| арифметика          | `add adc sub sbb cmp inc dec neg mul imul div idiv cbw cwde cwd cdq daa das aaa aas` |
| логика и сдвиги     | `and or xor not test shl sal shr sar rol ror rcl rcr` |
| биты                | `bt bts btr btc bsf bsr bswap set<усл> cmov<усл>` |
| переходы и вызовы   | `jmp call ret retf iret iretd j<усл> loop loope loopne jcxz jecxz int int3 into enter leave` |
| строковые           | `movsb/w/d cmpsb/w/d stosb/w/d lodsb/w/d scasb/w/d insb/w/d outsb/w/d` с префиксами `rep repe repz repne repnz` |
| порты               | `in out` |
| флаги               | `cli sti cld std clc stc cmc lahf sahf` |
| системные           | `lgdt lidt sgdt sidt lldt sldt ltr str lmsw smsw invlpg clts hlt cpuid rdtsc rdmsr wrmsr wbinvd invd ud2 nop pause wait xlatb` |

### Операнды

```
mov ax - bx                  ; регистр
mov ax - 0x1234              ; число или выражение
mov si - msg                 ; адрес метки
mov ax - [msg]               ; память по адресу
mov al - [bx+si+4]           ; 16-битная адресация: bx/bp + si/di + смещение
mov eax - [ebx+ecx*4+8]      ; 32-битная адресация с масштабом 1, 2, 4, 8
mov ax - [es:di]             ; сегмент (можно и так: es:[di])
mov byte [bx] - 5            ; размер, если его нельзя понять из регистра:
mov word [bx] - 5            ;   byte / word / dword (коротко: b / w / d)
jmp short метка              ; принудительно короткий переход
jmp 0x08:pm_start            ; дальний переход сегмент:смещение
jmp far [ptr]                ; дальний переход по адресу в памяти
rep stosb                    ; префиксы rep, lock, es/cs/ss/ds/fs/gs
mov cr0 - eax                ; управляющие регистры
mov si - "Hello"             ; адрес строки (компилятор положит её в pool)
push eax - ebx - ecx         ; несколько регистров сразу…
pop eax - ebx - ecx          ; …pop снимает в обратном порядке, список тот же
```

Короткие формы выбираются автоматически: переход занимает 2 байта, если цель
близко (−128…+127), иначе 3 (или 5 в `b 32`); число в `add bx - 5` кодируется
одним байтом и т. д. Машинный код совпадает байт в байт с NASM — это проверяется
тестами на сотнях форм команд.

## Порты (абстракции)

| Gasem          | Что делает                 |
|----------------|----------------------------|
| `mov a20 - 1`  | включить линию A20         |
| `mov a20 - 0`  | выключить линию A20        |

Используется «быстрый» способ через системный порт `0x92`. Регистр `ax`
(`eax` в `b 32`) сохраняется. `mov a20 - 1` разворачивается в:

```
push ax
in al - 0x92
or al - 2        ; бит 1 — A20
and al - 0xFE    ; бит 0 (сброс машины) никогда не ставим
out 0x92 - al
pop ax
```

## Данные

| Запись           | Что получается                                                  |
|------------------|-----------------------------------------------------------------|
| `b:`             | 0 байт — только метка (буфер, который «растёт» за конец программы) |
| `b: "Hello"`     | байты по содержимому: `48 65 6C 6C 6F`                          |
| `b: "Hello" - 0` | несколько значений через ` - `: строка и нулевой байт           |
| `s: "Hello"`     | строка с нулём в конце — то же, что `b: "Hello" - 0`            |
| `b-N`            | ровно N байт, заполненных нулями                                |
| `b/ N: значения` | ровно N байт, начало заполняется значениями, остаток — нулями. Инициализация обязательна, N > 0, значения не длиннее N |
| `w:` `w-N` `w/ N:` | то же для слов (2 байта)                                      |
| `d:` `d-N` `d/ N:` | то же для двойных слов (4 байта)                              |
| `q:` `q-N` `q/ N:` | то же для 8-байтных значений (удобно для GDT)                 |
| `&& N b: 0`      | повторение: любая строка данных или команда N раз              |
| `w: 0xAA55`      | слово (байты `55 AA`)                                           |

Перед данными можно поставить имя переменной: `msg s: "Hello"`,
`buf b-512`, `count w: 0`. Числа, не помещающиеся в элемент, — ошибка.

## Выражения

Операторы (от низшего приоритета к высшему):

| Приоритет | Операторы          |
|-----------|--------------------|
| 1         | `\|`               |
| 2         | `^`                |
| 3         | `&`                |
| 4         | `<<` `>>`          |
| 5         | `+` `-`            |
| 6         | `*` `/` `%`        |
| 7         | унарные `-` `+` `~`|

- `$` — адрес текущей строки, `$$` — адрес начала программы (значение `og`).
- `510-($-$$)` — сколько байт осталось до сигнатуры загрузочного сектора.

## Выражения do

```
do "выражение" - приёмник
```

Кавычки обязательны. Выражение **вычисляется при компиляции**, результат
кладётся в приёмник (регистр или память):

- если результат — **число**, получается `mov приёмник - число`;
- если результат — **строка**, компилятор помещает её прямо в код (с переходом
  в обход и завершающим нулём), а в приёмник записывает **адрес** строки.
  Одинаковые строки хранятся один раз.

Внутри выражения:

| Запись   | Значение                                                         |
|----------|------------------------------------------------------------------|
| `[msg]`  | всё значение переменной `msg`, как оно объявлено (строка — целиком, до нулевого байта; одно число — число) |
| `msg`    | адрес                                                            |
| `+`      | для чисел — сложение, для строк — конкатенация (число превращается в текст) |
| `'текст'`| строковая константа                                              |
| `- * / % & \| ^ << >> ~` | только для чисел                                  |

Примеры (при `msg b: "Hello" - 0` и `f b: "World" - 0`):

| Gasem                   | Результат                     |
|-------------------------|-------------------------------|
| `do "4+4" - ax`         | `ax = 8`                      |
| `do "[msg]" - ax`       | `ax` → строка `"Hello"`       |
| `do "[msg] + 1" - ax`   | `ax` → строка `"Hello1"`      |
| `do "[msg] + [f]" - ax` | `ax` → строка `"HelloWorld"`  |
| `do "msg + 2" - si`     | `si = адрес msg + 2`          |

Регистры в выражении `do` использовать нельзя — оно вычисляется во время
компиляции, а не во время работы программы.

## Управляющие конструкции

Ветвления и циклы без ручных меток и переходов. Компилятор сам ставит
сравнения, условные переходы и служебные метки — в листинге видно, во что
превратилась каждая строка. Блоки можно вкладывать друг в друга.

```
if al = 10                      ; ветвление
    call line_feed
elif al >= 'a' and al <= 'z'
    xor al - 0x20
else
    call putc
end

while byte [esi] != 0           ; цикл с условием
    inc esi
end

for ecx - 0 - 256               ; ecx = 0, 1, ..., 255
    call set_gate
end
for ecx - 10 - 0 - -1           ; ecx = 10, 9, ..., 1 (шаг -1)
    ...
end

repeat                          ; цикл с проверкой в конце
    in al - dx
    chk al - 0x80
until zero

while 1                         ; бесконечный цикл
    call getchar
    if al = 27
        break                   ; выйти из цикла
    end
    if al < ' '
        continue                ; следующий шаг цикла
    end
    call putc
end
```

| Конструкция                         | Что делает                                               |
|-------------------------------------|----------------------------------------------------------|
| `if` / `elif` / `else` / `end`      | ветвление; `elif` и `else` необязательны                  |
| `while условие` … `end`             | пока условие истинно                                     |
| `for счётчик - начало - конец [- шаг]` … `end` | счётчик от начала до конца (конец не включается); шаг — число, по умолчанию 1 |
| `repeat` … `until условие`          | тело выполняется хотя бы раз                              |
| `break`, `continue`                 | выйти из ближайшего цикла / перейти к следующему шагу     |

**Условия:**

| Запись                         | Значение                                                     |
|--------------------------------|--------------------------------------------------------------|
| `a = b`, `a != b`              | равно, не равно (`==` тоже работает)                          |
| `a < b`, `a > b`, `a <= b`, `a >= b` | сравнение **без знака** (адреса, символы, счётчики)    |
| `signed …`                     | сравнение со знаком: `if signed eax < 0`, `for signed ecx - -5 - 5` |
| `x` / `not x`                  | регистр или память не равны нулю / равны нулю: `while byte [esi]` |
| `zero`, `carry`, `sign`, `overflow`, `parity` | флаг после предыдущей команды; `not zero` и т. п. |
| `… and …`, `… or …`            | несколько условий (`and` связывает сильнее `or`), вычисляются по порядку и не дальше, чем нужно |

Слева в сравнении — регистр или память, справа — регистр, память или число.
Сравнение регистра с нулём превращается в короткое `chk r - r`.

### Условие в конце строки

Любую команду можно выполнить при условии, дописав `if` в конце строки:

```
ret if carry                 ; вместо трёх строк if carry / ret / end
inc bx if zero
break if al = 27             ; внутри цикла
continue if not zero
jmp .fail if eax = 0         ; превращается в один условный переход: test / jz
```

## let — выражения во время работы программы

`do` вычисляет выражение **при компиляции**. Его пара `let` превращает выражение
в команды, которые считают его **во время работы** — с регистрами и памятью:

```
let ebx - "[cur_row]*80 + [cur_col]"       ; вместо трёх строк mov / imul / add
let eax - "(ebx + ecx) * (edx - 3) / esi"
let edi - "ebx*512 + FS_DIR"
let al - "byte [esi] - '0'"
let signed eax - "-ebx / 2"                ; деление и >> со знаком
let "eax + 1" - ebx                        ; можно и в порядке do: выражение - приёмник
```

| Можно использовать              | Как                                                     |
|---------------------------------|---------------------------------------------------------|
| регистры                        | `eax`, `bx`, `cl`… (меньшие расширяются нулями, в `signed` — со знаком) |
| память                          | `[x]`, `[esi+4]`, `byte [esi]`, `word [bx+si]`           |
| числа, константы, адреса меток  | `80`, `'A'`, `FS_DIR`, `msg`                             |
| операции                        | `+ - * / % & \| ^ << >> ~`, унарный минус, скобки        |

- Приёмник — регистр или память с указанным размером (`let dword [x] - "..."`).
- Меняется **только приёмник** (и флаги): если для вычисления нужны временные
  регистры, компилятор сохраняет их в стеке и восстанавливает.
- Деление и остаток без знака (`div`), в режиме `signed` — со знаком (`idiv`);
  `>>` — `shr` или `sar`. Умножение и деление на степень двойки становятся сдвигами.
- Части без регистров и памяти (`FS_DIR + 512`) вычисляются при компиляции.
- `esp`/`sp` в `let` использовать нельзя (временные значения лежат в стеке).
  Если выражение слишком сложное и свободных регистров не хватает, компилятор
  попросит разбить его на несколько `let`.

`let` проверяется тестом: сотни случайных выражений компилируются, выполняются
в эмуляторе x86 и сравниваются с ответом, посчитанным на Python, — заодно
проверяется, что остальные регистры не изменились.

## Строки в командах и pool

Строку можно писать прямо в команде — её **адрес** попадёт в операнд, а саму
строку (с нулём в конце) компилятор положит в данные. Одинаковые строки
хранятся один раз.

```
mov si - "Hello"
call puts - "Saved "             ; вызов с аргументом — см. ниже
```

Куда кладутся строки:

- `pool` — сюда попадают строки из команд, встретившихся выше (после предыдущего
  `pool`). Обычно его ставят в конце кода, перед данными. Можно несколько:
  в GasemOS один `pool` — в загрузочном секторе, другой — в конце ядра.
- если после команды `pool` нет, строка кладётся прямо в код, а перед ней —
  переход в обход (2 байта).

`'A'` в одинарных кавычках — по-прежнему символ (число). Если перепутать
(`mov al - "A"`), компилятор подскажет.

## Вызов с аргументами: call и args

```
args puts - esi                  ; puts принимает аргумент в esi
args set_pos - eax - ebx

call puts - "Hello"              ; mov esi - адрес "Hello" / call puts
call set_pos - 12 - 27           ; mov eax - 12 / mov ebx - 27 / call set_pos
jmp puts - "Bye"                 ; то же, но переход (хвостовой вызов)
```

- `args имя - регистры` объявляет, в каких регистрах подпрограмма ждёт
  аргументы. Объявление может стоять где угодно — до или после вызова.
- Без `args` аргументы идут в `eax`, `ebx`, `ecx`, `edx`, `esi`, `edi`
  (в `b 16` — `ax`, `bx`, …).
- Аргументом может быть число, метка, строка, регистр или память. Меньший регистр
  расширяется (`movzx`). Порядок пересылок компилятор выбирает сам, чтобы
  не затереть нужный регистр: `call f - 5 - eax` при `args f - eax - ebx`
  сначала делает `mov ebx - eax`. Если аргументы зависят друг от друга по
  кругу, будет ошибка.

## Пример загрузчика

```
og 0x7C00
b 16
xor ax - ax
mov ds - ax
mov si - msg
print:
    mov ah - 0x0E
    nxtb
    int 0x10
    chk al - al
    jfnz print
    jmp $

msg b: "Hello" - 0
&& 510-($-$$) b: 0
w: 0xAA55
```

Результат — ровно 512 байт с сигнатурой `55 AA` в конце. Обратите внимание:
в этом цикле символ печатается *до* проверки на ноль, поэтому завершающий `0`
тоже уходит на экран (как пустой символ). Чтобы этого не было, проверяйте
перед печатью — как в [`examples/do.gsm`](examples/do.gsm):

```
print:
    mov ah - 0x0E
.next:
    nxtb
    chk al - al
    jfz .done
    int 0x10
    jmp .next
.done:
    ret
```

## Ошибки, подсказки и предупреждения

Компилятор показывает файл, строку, саму строку и место ошибки, и по
возможности подсказывает, как исправить:

```
boot.gsm:4: ошибка: операнды разделяются ' - ' (дефис с пробелами), а не запятой
    mov ax, 1
          ^
boot.gsm:9: ошибка: отрицательное число повторений (-90): код не помещается в отведённое место (например, загрузочный сектор длиннее 510 байт)
    && 510-($-$$) b: 0
```

Опечатки он узнаёт — перестановку букв, лишнюю или пропущенную букву,
регистр букв, соседнюю клавишу:

```
boot.gsm:5: ошибка: неизвестная команда 'mvo' — может быть, 'mov'?
boot.gsm:7: ошибка: неизвестная команда 'nxbt' — может быть, 'nxtb'?
boot.gsm:9: ошибка: неизвестное имя 'prnit' — может быть, 'print'?
boot.gsm:9: ошибка: неизвестное имя 'ebz' — может быть, регистр 'ebx'?
boot.gsm:12: ошибка: неизвестная переменная 'mgs' — может быть, 'msg'?
```

Предупреждения не мешают сборке, но указывают на подозрительное — например,
метку, на которую нет ни одной ссылки (кроме первой метки программы — точки
входа). Отключаются параметром `-w`.

```
boot.gsm:20: предупреждение: метка 'old_print' нигде не используется
```

`gasem boot.gsm -l boot.lst` пишет таблицу «строка — адрес — байты — исходник»

## Инструменты

### Отладка: gasem debug

```sh
gasem debug boot.gsm -b print
```

Собирает программу, запускает её в QEMU остановленной и подключает GDB.
GDB знает метки и строки исходника Gasem:

| Команда в GDB      | Что делает                                                   |
|--------------------|--------------------------------------------------------------|
| `gbreak метка`     | точка останова на метке                                      |
| `gstep`            | выполнить одну строку `.gsm` (даже если это `let` из нескольких команд) |
| `gwhere`           | показать текущую строку                                      |
| `continue`, `info registers`, `x/8xb адрес` … | обычные команды GDB             |

При каждой остановке печатаются строка исходника и регистры:

```
=> boot.gsm:7    let bx - "cx*10 + 7"
   eax=00000000  ebx=00000000  ecx=00000003  edx=00000080  ...
```

`--batch` — без окон: дойти до первой точки останова, показать состояние и выйти
(удобно в скриптах). Нужны `qemu-system-i386` и `gdb`.

### Оформление: gasem fmt

```sh
gasem fmt os/*.gsm           # выровнять на месте
gasem fmt --check *.gsm      # только проверить (код выхода 1, если есть что менять)
gasem fmt --diff boot.gsm    # показать изменения
```

Сдвигает тела `if`/`while`/`for`/`repeat` на 4 пробела и выравнивает
комментарии в конце строк в один столбец. Меняются только пробелы — смысл
программы измениться не может (тесты проверяют, что GasemOS после `fmt`
собирается в те же байты).

### VS Code

В папке [`editors/vscode`](editors/vscode) — расширение: подсветка синтаксиса
(включая выражения внутри `do`/`let`), сниппеты (`boot`, `if`, `while`, `for`, …),
автоотступы в блоках. Установка — скопировать папку в `~/.vscode/extensions/`,
подробнее в её [README](editors/vscode/README.md). Грамматика генерируется из
таблиц компилятора, поэтому знает все те же команды и регистры.

## Устройство компилятора

| Файл                 | Назначение                                                      |
|----------------------|-----------------------------------------------------------------|
| `gasem/lexer.py`     | токены; распознаёт разделитель ` - ` по пробелам вокруг дефиса   |
| `gasem/parser.py`    | разбор строк: метки, директивы, данные, команды, операнды, `do`  |
| `gasem/expr.py`      | вычисление выражений (числа и строки)                           |
| `gasem/highlevel.py` | `if`/`while`/`for`/`repeat` и `let` → обычные команды и метки   |
| `gasem/hints.py`     | подсказки «может быть, вы имели в виду…»                         |
| `gasem/fmt.py`       | `gasem fmt`                                                     |
| `gasem/debug.py`     | `gasem debug`: QEMU + GDB с метками и строками исходника         |
| `gasem/assembler.py` | многопроходная сборка: адреса меток, `&&`, данные, `do`, листинг |
| `gasem/x86.py`       | кодирование команд x86 в машинный код (ModRM/SIB, префиксы)     |
| `gasem/cli.py`       | командная строка                                                |

Можно использовать и из Python:

```python
from gasem import compile_source
code = compile_source('og 0x7C00\njmp $\n&& 510-($-$$) b: 0\nw: 0xAA55').code
```

```sh
python3 -m unittest discover -s tests
```

- `tests/test_language.py` — директивы, данные, `do`, метки, сообщения об ошибках;

  байт в байт с NASM (пропускается, если `nasm` не установлен);
- `tests/test_boot.py` — примеры запускаются в эмуляторе x86 и проверяется, что
  они напечатали / записали в видеопамять (нужен `pip install unicorn`, иначе
  пропускается).
- `tests/test_highlevel.py` — `if`/`while`/`for`/`repeat` и `let` выполняются в
  эмуляторе; для `let` — сотни случайных выражений в режимах 16 и 32 бит;
- `tests/test_conveniences.py` — `s:`, списки в `push`/`pop`, условие в конце строки,
  строки в командах, `pool`, `call` с аргументами, подсказки и предупреждения;
- `tests/test_tools.py` — `gasem fmt` (на всех исходниках меняются только пробелы,
  GasemOS собирается в те же байты), грамматика VS Code, сниппеты, командная
  строка, отладка в QEMU + GDB;
- `tests/test_os.py` — GasemOS собирается, загружается в QEMU, выполняет
  команды; файлы, записанные на диск, остаются после выключения и повторной
  загрузки (пропускается, если QEMU не установлен).
